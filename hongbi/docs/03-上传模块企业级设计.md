## 一、解析与数据核心

### 1.1 六阶段解析管线
见 [03-上传模块企业级设计.md](03-上传模块企业级设计.md) 第 3 节（提取→归一化→多策略→验证→人工修正→入库）。本版固化为：

- `server/parser/index.js`：管线编排，返回 `ParseResult = { document, questions[], qualityReport, errors[] }`。
- 每个阶段独立文件、独立错误码、独立单元测试。

### 1.2 题目统一模型
```js
QuestionModel {
  id, setId, idx, fingerprint,            // 指纹见 1.3
  q, options[], answer, explanation, type, // choice | multi | text | calc | case
  media[],                                // [{type:'image', url}]
  confidence, issues[], raw,               // 解析期信息（入库后保留 issues 供展示）
  status: 'active'|'deprecated'|'edited'  // 版本管理用
}
```

### 1.3 题目指纹与引用稳定（重点）
**问题**：重新上传更新题库时，题库被整体替换 → 错题本/收藏引用的 question_id 失效。

**设计**：
- `questions.fingerprint`：对 `归一化(q) + 归一化(options) + 归一化(answer)` 做 SHA-256 摘要。
- 重新上传（同 set 更新）：按 fingerprint 匹配旧题目 → **沿用旧 question_id**（错题/收藏引用不断）；新增题建新 id；旧题标记 `deprecated`（不再出现但历史引用仍可读）。
- 匹配规则：指纹相同直接复用；指纹不同但题干相同（仅答案修正）→ 标记 `edited` 并更新字段（引用保留）。
- 配套：`GET /api/sets/:id/diff?baseVersion=` 预览新旧差异（新增/更新/删除 N 题）。

### 1.4 题库版本管理
- `sets.version`（从 1 递增）+ `sets_versions` 表（版本快照：title/desc/questions 摘要/创建时间/操作者）。
- 重新上传默认创建新版本（`uploadMode: replace` 原地升版 | `new` 新建副本，上传时选择）。
- 管理端「历史版本」列表 + 一键回滚（切回旧版本题目集，question_id 仍稳定）。
- `sets.status`：active | archived（隐藏不删）。

### 1.5 幂等去重
- 上传创建 set 前：计算全套题目指纹集合哈希 → 与现存公共/私库比对，命中提示「已存在相同内容题库（xx 题）」，可选择「仍要上传/取消」。

### 1.6 入库事务
- 建题库 + 写题目 + 写版本快照 在一个事务内；失败整体回滚，job 记录失败原因。

### 1.7 数据库迁移管理
- `server/migrate.js`：迁移文件列表 `[ {version, up(db)} ]`，启动时按序执行并记录 `schema_versions` 表；CI 与部署自动跑。

## 二、上传任务与性能

### 2.1 任务队列
- `upload_jobs` 扩展字段：`stage`（upload/extract/parse/validate/review）、`progress`、`attempts`、`last_error`、`priority`。
- 队列：内存队列 + `MAX_CONCURRENT`（默认 2，可配）；排队中任务前端显示「排队中（第 N 位）」。
- 超时：单任务 `PARSE_TIMEOUT_MS`（默认 10 分钟）→ 失败 + 原因。
- 取消：`POST /api/upload/:id/cancel`（仅排队/解析中）。
- 重试：失败任务可「重试」（重新入队，attempts+1，上限 3）。

### 2.2 大文件与内存
- multer diskStorage 落盘（不占内存）；解析按流/分块读入（>20MB 走流式读取）。
- 临时文件目录 `server/data/tmp/`，任务终态（done/failed/cancel）后立即删除；启动时清理孤儿临时文件。

### 2.3 解析隔离
- 解析在 worker 上下文执行（`worker_threads` 或子进程），解析器崩溃不影响主进程；超时强杀。

### 2.4 批量上传
- `POST /api/uploads`（multipart 多文件，或单个 zip）。
- zip：白名单内文件逐个入队（单 zip 限 20 个文件 / 100MB）；每个文件独立 job，独立报告。
- 前端「批量上传」页：文件列表 + 各自状态。

### 2.5 模板下载
- 提供标准模板（TXT / JSON / Word 示例）：`GET /api/upload/templates/:type`；上传页常驻入口。

## 三、安全

### 3.1 魔数校验（防伪装）
- 文件识别表：zip(PK\x03\x04) → docx/xlsx；`%PDF` → pdf；UTF-8/GBK 文本探测 → txt 类。
- 扩展名与魔数不一致 → 拒绝，原因「文件内容与扩展名不符」。

### 3.2 docx 宏/脚本剥离
- 解析 docx 时检查 zip 内 `word/vbaProject.bin`、`word/vbaData.xml`：存在 → 剥离（不读取）+ 报告警告「已移除宏内容」。
- 提取时仅读取 `word/document.xml` 纯文本，不解析任何其他活动内容。

### 3.3 速率限制与配额
- 自研内存限流中间件：每身份（token）`上传次数/小时`（默认 20）、`上传字节/天`（默认 500MB）。
- 持久配额：`users.upload_bytes_total`、`sets 数上限`（默认 500）——超限提示升级。
- 公共上传额外限速（防刷）。

### 3.4 内容注入清洗
- 入库前对 q/options/answer/explanation 执行 `sanitizeText()`：剥离 HTML 标签、`<script>` 等危险片段、控制字符；限制长度（沿用 5000/500/2000/3000）。
- 前端渲染统一 `esc()`（已有），双保险。

### 3.5 版权确认（合规）
- 上传确认步骤加**必勾选**：`我已确认拥有该题库版权或已获授权，同意共享规则`。
- 未勾选不可提交；`sets.copyright_confirmed` 落库；审核页展示该字段。
- 共享协议文案升级为合规版本（含「侵权内容将被下架」条款）。

## 四、多用户与权限

### 4.1 角色与权限矩阵
| 操作 | user | admin | superadmin |
| --- | --- | --- | --- |
| 上传（私库/共享提交） | ✓ | ✓ | ✓ |
| 编辑/删除自己的题 | ✓ | ✓ | ✓ |
| 审核队列 | — | ✓ | ✓ |
| 驳回/批准（含原因） | — | ✓ | ✓ |
| 删除他人公共题 | — | ✓ | ✓ |
| 管理管理员（设/撤 admin） | — | — | ✓ |
| 全局配置/审计查询 | — | — | ✓ |
- 中间件 `requireRole(...)` 已具备，补「删除他人公共题」「管理管理员」接口。

### 4.2 审核闭环
- 状态机：`pending → approved | rejected → (编辑后 resubmit) → pending`
- 驳回后可「修改后重新提交」（`POST /api/sets/:id/resubmit`，需重新走解析或直接改内容后提交）。
- 审核页展示：上传者、版权确认、质量报告、预览、历史审核记录。

### 4.3 私有题库访问控制
- 私库仅 owner 可见（现状）；新增**分享链接**：`POST /api/sets/:id/share` 生成带 token 链接（7 天有效/可撤销），匿名可读（不写权限）。
- 列表接口默认不含分享态细节。

### 4.4 审计日志
- `audit_logs` 表：`id, actor_id, actor_type, action, target_type, target_id, detail(json), ip, created_at`。
- 记录动作：上传提交、审核批准/驳回、删除（含他人）、编辑、版本回滚、管理员变更、分享创建/撤销、导出。
- 查询接口（superadmin）：`GET /api/admin/audit?action=&actor=&target=&page=`。

## 五、可观测性与运维

### 5.1 结构化日志
- `server/logger.js`：JSON 行日志（ts, level, jobId, reqId, event, meta）。
- 请求中间件生成 reqId，任务链路贯穿 jobId。
- 日志级别可配；文件轮转（按大小/天，保留 N 份）。

### 5.2 解析质量看板（管理端）
- `GET /api/admin/stats/parser`：按日聚合——任务数、成功率、平均覆盖率、失败原因 TopN、平均耗时。
- 数据源：upload_jobs + 质量报告快照（job 落一份 quality JSON）。
- 前端「管理 → 解析质量」页：表格 + 趋势。

### 5.3 备份与恢复
- `npm run backup`：WAL checkpoint → 复制 hongbi.db（+ -wal/-shm 合并）→ 输出 `backups/hongbi-YYYYMMDD-HHmm.db`（保留 7 份）。
- `npm run restore <file>`：停服说明 + 替换 db（文档）。
- 建议部署方配 cron 每日备份（docker-compose 提供示例）。

### 5.4 部署化
- `Dockerfile`（node:22-slim + 工作目录 + volume 挂 data/）+ `docker-compose.yml`（服务 + 数据卷 + 备份 sidecar 示例）。
- 配置全部环境变量化（见 README 环境变量表，新增：`MAX_CONCURRENT`、`PARSE_TIMEOUT_MS`、`RATE_LIMIT_*`、`BACKUP_KEEP`）。
- 进程守护：容器内 tini/node 直接前台；非容器环境提供 systemd unit 示例。

## 七、题型与内容扩展

### 7.1 图片/材料题
- `questions.media`：`[{type:'image', url}]`（题干图/选项图/材料图）。
- 存储：FileStore 接口 → 本地 `data/media/`（按 setId/题 id 组织）；管理端上传接口 `POST /api/media`（限 5MB/图、类型 png/jpg/webp）。
- 前端：题干/选项渲染 `<img>`；上传解析时提取 docx/pdf 中的图片（docx 解包 `word/media/`、pdf 页面转图留待 OCR 阶段）——v1 先支持「解析文档内嵌图片关联到题」+ 人工修正时手动上传图片。
- 图形推理题（无文字提取）识别：区块无文字但有图 → 标记「图片题，需人工补充题干」。

### 7.2 题型扩展
- type 增加 `calc`（计算题）/`case`（案例分析）：结构与 text 一致，刷题走简答流程，仅标签区分。
- 判断题已支持（正确/错误选项）。

### 7.3 数学公式
- 低优先级：题目文本支持 LaTeX 片段（`$...$`）渲染（前端引入 KaTeX CDN 可选），不阻塞解析。

## 九、升级预留

### 9.1 数据访问层抽象（Repo）
- `server/repo/*.js`：所有 SQL 封装为函数（`repo.sets.get(id)`、`repo.questions.bySet(...)`…），API/领域层不直接写 SQL。
- 当前实现用 node:sqlite；接口签名对齐 PG 版（预留 `repo/pg/` 目录与说明）。

### 9.2 存储接口化（FileStore）
- `server/storage/fileStore.js`：`save(stream, key)` / `read(key)` / `delete(key)` / `url(key)`。
- 实现：`LocalStore`（现用）；预留 `OssStore`（key 前缀抽象，迁移只换实现）。
- 上传临时文件、媒体图片均走 FileStore。

### 9.3 任务与 API 分离演进
- 解析执行抽为独立模块 `server/parser/worker.js`（当前同进程 setImmediate 调用；预留独立 worker 进程/消息队列，接口 `enqueueParse(jobId)`）。

## 十一、验收标准

1. 全部 38 项要点落地，无「打补丁式」代码残留（解析器无新增格式需改主逻辑）。
2. 现有 6 类已知格式覆盖率 ≥95%；未知格式产出可读报告不崩溃。
3. 重新上传题库：错题/收藏引用零断裂（指纹机制）。
4. `npm test` 全绿；审计/限流/版权/宏剥离均有测试覆盖。
5. 部署：一条命令（docker compose up）可跑；备份/恢复可用。
