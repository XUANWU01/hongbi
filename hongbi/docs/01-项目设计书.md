# 红笔 HONGBI · 项目设计书 v2.0

> 版本：v2.0 ｜ 日期：2026-08-01 ｜ 状态：设计定稿，进入实现
> 本文档为「红笔 v1」（上传→共享确认→刷题→错题本）的重新设计稿，所有代码由 AI 实现。

## 1. 项目定位

**一句话**：一个"题库民主化"的刷题工具 —— 任何人上传自己的题库文档，经共享确认后合并进公共主题库，让有同样需求的人直接使用；不同意共享的题库进入个人私库。

**与 v1 的差异（本版目标）**

| 维度 | v1 | v2 |
| --- | --- | --- |
| 架构 | 静态前端 + 零依赖后端（最小可用） | 模块化前端 + 升级版 API（题库/题目/答题/收藏分层） |
| 题库广场 | 全量列表，本地过滤 | 服务端搜索、分类、分页、排序 |
| 刷题 | 单模式（随机） | 顺序/随机/每日一练 三种模式 |
| 错题本 | 列表 + 专项重刷 | 按错误次数排序 + 复习建议 |
| 题目管理 | 不可改 | 可追加题目、编辑元信息 |
| 收藏 | 无 | 题目收藏（星标） |
| 统计 | 汇总数字 | 正确率近 7 天趋势 |
| 体验 | 基础响应式 | 键盘快捷键、深色模式、移动端底部导航 |

## 2. 用户画像与核心场景

**画像 A：考证/应试者**（主用户）
- 场景：考前把机构发的题库 PDF/Word 传上来，同意共享到主题库；错题进错题本，考前专项重刷。
- 诉求：上传识别率、错题复习、不要打扰。

**画像 B：内容贡献者**
- 场景：整理了一份高质量题库，选择共享，成为"我的贡献"，可管理（改描述、追加题目、删除）。
- 诉求：贡献被标记、可撤回、操作成本低。

**画像 C：局域网/小团体管理员**
- 场景：在教室/办公室跑 `node server/server.js`，全班访问同一公共题库。
- 诉求：一键启动、数据持久、可设管理密钥。

**核心用户故事**
1. 作为考生，我上传 Word 题库时被明确告知"将合并进公共主题库"，我选择同意或建立私库。
2. 作为考生，我刷题时能看答案、标记认识/不认识，不认识的自动进错题本。
3. 作为考生，我打开错题本能看到"答错次数"并按优先级复习。
4. 作为贡献者，我能在"我的题库"里看到我的贡献，并修改描述、追加题目。
5. 作为管理员，我能设置密钥防止他人删除共享题库。

## 3. 功能设计

### 3.1 信息架构

```
红笔 v2
├── 工作台（首页）
│   ├── 今日速览（题目总数/累计作答/正确率/错题数）
│   ├── 正确率趋势（近 7 天）
│   ├── 快捷入口（继续刷题/刷错题/每日一练/上传）
│   └── 最近动态
├── 题库广场
│   ├── 搜索框（标题/标签/分类）
│   ├── 分类筛选（计算机/前端/语言/数学/历史/职场/常识/其他）
│   ├── 排序（最新/题量/人气）
│   ├── 分页
│   └── 卡片：标题/分类/来源标签/题数/正确率 → 开始刷题/预览
├── 刷题
│   ├── 模式选择（顺序/随机/每日一练 10 题）
│   ├── 题目卡片（选择题即时判对错 / 简答显示答案后自评）
│   ├── 收藏按钮、键盘快捷键
│   ├── 进度条 + 实时答对数
│   └── 结果页（正确率环/错题回顾/重刷错题/再刷一轮）
├── 我的题库
│   ├── 我的私库（增删/导出/预览）
│   ├── 我的贡献（改描述/追加题目/删除）
│   └── 导出 JSON / CSV
├── 错题本
│   ├── 按题库分组，组内按答错次数降序
│   ├── 复习建议（答错 ≥3 次：加急；1-2 次：巩固）
│   ├── 已掌握 / 专项重刷 / 清空
└── 上传
    ├── 拖拽/选择（JSON/TXT/MD/CSV/TSV/PDF/DOCX）
    ├── 解析核对（格式/题数/样例/警告，折叠显示）
    ├── 元信息（标题/分类/标签/描述）
    └── 共享确认（同意→公共主题库 / 不同意→私库）
```

### 3.2 关键流程

**上传 → 共享确认（强制）**
1. 选文件（文本 ≤2MB，PDF/Word ≤20MB；PDF/Word 首次需联网加载解析库）。
2. 解析预览：显示格式、题数、前 3 题样例、警告（最多折叠 5 条 + N）。
3. 填写元信息。
4. 红色「共享协议」区块（不可跳过）：
   - 同意 → 云端模式 POST 服务器 / 本地模式存本地公共库；
   - 不同意 → 存私库（仅本机）；
   - 云端提交失败 → 保留表单，可重试或转私库。
5. 入库提示 + 跳转对应页面。

**刷题闭环**
1. 题库卡 → 开始刷题（或选模式）。
2. 选择题：点选项即时判对错（蓝=对/红=错），展示答案与解析；简答：显示答案 → 认识/不认识。
3. 答错/不认识 → 记入错题本（计数 +1）。
4. 结束 → 结果页（正确率环 + 错题回顾）→ 可重刷错题（答对自动移出）。
5. 错题本 → 已掌握移除 / 专项重刷 / 按次数排序。

**模式切换（云端/本地）**
- 启动探测 `/api/health`（2.5s 超时）：成功 → ☁ 云端共享；失败 → 本地模式。
- 两种模式共用同一套 UI 与数据模型，仅公共题库的数据源不同。

### 3.3 交互与体验细节

1. 键盘快捷键（刷题页）：`A/B/C/D` 选答案、`空格` 显示答案、`回车` 下一题、`F` 收藏、`Q` 退出。
2. 深色模式：顶栏月亮按钮切换（localStorage 记忆），纸墨色系夜晚版。
3. 收藏：题目右上角星标，收藏页（错题本旁新增「收藏」入口，或并入我的题库）。
4. 空状态：每页都有带引导的空状态（图标 + 文案 + CTA）。
5. 动效：页面切换渐入、卡片 stagger 入场、印章弹出；`prefers-reduced-motion` 全禁用。
6. 无障碍：按钮 aria-label、焦点可见、模态焦点管理、颜色对比 ≥ 4.5:1。
7. 移动端：≤860px 底部导航栏（工作台/广场/上传/我的/错题）。

## 4. 技术架构

### 4.1 总览

```
浏览器（原生 JS，无构建）
├── core.js   工具/存储/事件/模态/toast
├── api.js    服务端客户端（云端/本地自动切换）
├── parser.js 题库解析器（复用 v1，含选项安全校验）
├── store.js  本地数据层（私库/进度/错题/收藏/统计/偏好）
├── views.js  视图渲染（home/library/quiz/mine/wrong/upload/fav）
└── app.js    路由/启动/全局事件

Node 后端（零依赖：http + node:sqlite，无 npm 依赖）
└── server.js 静态托管 + REST API
    └── seed.js 官方种子题库
```

- 前端不构建、不打包，浏览器直接加载；后端仅用 Node 内置模块。
- 个人数据（私库、进度、错题、收藏、统计）留在浏览器 localStorage；公共题库上服务器。

### 4.2 数据字典（SQLite）

| 表 | 字段 | 说明 |
| --- | --- | --- |
| `sets` | id, title, desc, category, tags(JSON), source(official/public), owner(clientId), created_at, updated_at | 题库 |
| `questions` | id, set_id, idx, q, options(JSON), answer, explanation, type | 题目（拆表，支持追加/统计） |
| `clients` | id, created_at | 设备标识（贡献归属） |
| `attempts` | id, set_id, question_id, client_id, correct, created_at | 云端答题流水（聚合"人气"） |
| `favorites` | id, set_id, question_id, client_id, created_at | 云端收藏 |
| `wrong_items` | id, set_id, question_id, client_id, count, last_at | 云端错题（冗余，便于换设备） |

> 本地模式数据模型（localStorage）：`hb_public/hb_private/hb_progress/hb_wrong/hb_fav/hb_stats/hb_pref`。

### 4.3 API 设计

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/health` | 健康检查（前端探测用） |
| GET | `/api/sets?search=&cat=&sort=&page=&size=` | 公共题库分页搜索（服务端过滤） |
| GET | `/api/sets/:id` | 题库详情（含题目） |
| POST | `/api/sets` | 创建（同意共享；校验 + 标题重复检测） |
| PATCH | `/api/sets/:id` | 改元信息（owner 或 admin） |
| DELETE | `/api/sets/:id` | 删除（owner 或 admin；official 禁删） |
| POST | `/api/sets/:id/questions` | 追加题目（owner） |
| POST | `/api/attempts` | 答题流水上报 |
| POST | `/api/favorites` ／ DELETE `/api/favorites/:id` | 收藏/取消 |
| GET | `/api/stats/global` | 平台统计（题库数/题目数） |

- 校验：标题 1-60 字；题目 1-800 条；字段长度上限；请求体 ≤5MB。
- 安全：clientId 由前端生成并随请求提交（贡献归属）；可选 `HONGBI_ADMIN_KEY` 环境变量，设置后删除/修改接口需 `x-admin-key` 头；CORS 全开。
- 兼容：v1 数据库自动迁移（旧 `sets.questions` JSON → 新 `questions` 表）。

### 4.4 解析器规则（复用 v1 + 已知修复）

- 支持 JSON/TXT/MD/CSV/TSV/PDF/DOCX；UTF-8。
- 选项安全校验：同行选项必须从 A 开始严格递增；行首选项同样校验，防止英文片段（`e.xml`）误拆。
- 无答案题目给警告（预览折叠展示），不阻断上传。

## 5. 非功能需求与验收

| 项 | 要求 |
| --- | --- |
| 兼容 | Chrome/Edge 最新 2 个版本；Node ≥ 22.5（使用内置 sqlite） |
| 性能 | 广场分页 ≤ 50ms；题库详情 ≤ 100ms；首屏无网络时可离线使用核心功能 |
| 数据 | 公共题库服务器持久化；个人数据本机；导出 JSON/CSV 可迁移 |
| 安全 | 官方题库禁删；管理密钥可选；所有用户内容渲染前 HTML 转义（防 XSS） |
| 可访问性 | 键盘可操作、焦点可见、aria 标签、reduced-motion |
| 代码 | 零 npm 依赖、零构建；`node --check` 全绿；解析器单测 ≥ 15 条 |

**验收清单（实现完成时逐项勾选）**
- [ ] 上传 6 种格式解析正确；共享确认两种去向均生效
- [ ] 云端模式：跨用户可见、贡献归属、删除权限正确；停服自动回退本地
- [ ] 刷题三模式可用；错题计数/已掌握/专项重刷正确
- [ ] 收藏、趋势图、深色模式、快捷键、移动端导航可用
- [ ] v1 数据库自动迁移，历史题库不丢
- [ ] 浏览器实测全流程 + 控制台零报错
