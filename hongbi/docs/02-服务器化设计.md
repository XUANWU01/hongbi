# 红笔 HONGBI v3 · 服务器化改造设计（定稿版）

> 状态：**已确认，进入实现**（2026-08-02）
> 目标：把题库数据、文档解析、刷题进度、错题、收藏、统计全部收归服务器；浏览器只做展示与交互。

## 1. 背景：现在的问题

| 现状 | 问题 |
| --- | --- |
| 2048 题题库存浏览器 localStorage | 逼近 5MB 配额；每台设备各存一份；私库越大越卡 |
| 解析在浏览器端（pdf.js/JSZip CDN） | 依赖联网加载解析库、占用浏览器内存、解析耗时 |
| 进度/错题/收藏/统计在 localStorage | 换设备全丢；没有账号概念 |
| 题库详情整库下传（2048 题一次拉取） | 首次进入刷题页加载慢 |

## 2. 设计目标

1. 浏览器端只保留：静态页面 + 交互逻辑 + 轻量缓存（<50KB）。
2. 所有持久数据（题库/题目/进度/错题/收藏/统计）由服务器 SQLite 统一管理。
3. 文档解析移到服务器：浏览器只上传原文件，拿到结构化结果。
4. 刷题题目分批加载（一次 20 题），不再整库下传。
5. 保留「共享确认」流程与云端/公共库语义，并升级为真正的账号体系。

## 3. 架构总览

```
浏览器（原生 JS 轻客户端，~150KB，零框架）
├── app.js / views.js     页面与交互（瘦身版，移除解析器与大存储）
├── api.js                API 客户端 + token 会话
└── cache.js              SessionStorage 轻缓存（当前会话题、主题偏好）

Node.js 服务器（http + node:sqlite，可选 Express）
├── 静态托管            前端文件
├── /api/auth            账号 / 设备登录
├── /api/upload          文件上传 → 服务器解析 → 解析预览
├── /api/sets            题库 CRUD（公共库 + 私库）
├── /api/questions       题目分批加载
├── /api/quiz            刷题会话：出题 / 答题 / 进度
├── /api/wrong|fav|stats 错题 / 收藏 / 统计
└── /api/import          旧 localStorage 数据迁移导入
```

**数据流（上传）**
选文件 → `POST /api/upload`（文件流）→ 服务器解析（docx 解包 + 文本状态机；PDF 用 pdfjs-dist）→ 返回 `{format, total, samples, warnings}` → 浏览器展示预览 → 用户确认共享/私库 → `POST /api/sets` 正式入库。

**数据流（刷题）**
`POST /api/quiz/:setId/start` 建会话 → `GET /api/quiz/:setId/questions?offset=&limit=20` 分批取题 → 前端作答（选择题即时判对 / 简答自评）→ `POST /api/quiz/answer`（服务器记录进度/错题/统计）→ 结束 `POST /api/quiz/:id/finish` 汇总。

## 4. 技术栈与运行

| 项 | 选择 | 理由 |
| --- | --- | --- |
| 运行时 | Node ≥ 22.5 | 内置 `node:sqlite`，无原生编译 |
| HTTP | Express（推荐）或继续零依赖 | Express 让路由/上传/静态托管更清晰；需要一次 `npm install` |
| 数据库 | SQLite（`node:sqlite`） | 单文件、零运维，局域网/单机够用 |
| 上传 | `multer`（Express 生态）或自写流式接收 | 限 20MB |
| PDF 解析 | `pdfjs-dist`（服务器端） | 纯 JS，Node 可跑 |
| DOCX 解析 | 自研 zip 解包 + document.xml 提取 | 已有 Python 验证过的提取逻辑，移植为 JS |
| 文本解析 | 现有 `parser.js` 状态机（原样迁移到服务器） | 已适配辅警题库等 10+ 种格式 |
| 密码 | `node:crypto` scrypt 哈希 | 无第三方依赖 |
| 静态缓存 | `Cache-Control` + ETag | 前端资源版本号防缓存坑 |

## 5. 数据模型（SQLite）

```
users         id, username UNIQUE, pass_hash, salt, created_at
sessions      token, user_id, device_id, created_at, expires_at
devices       id, label, created_at          （匿名设备登录用）
sets          id, title, desc, category, tags, source(official|public|private), owner_user_id, created_at, updated_at
questions     id, set_id, idx, q, options, answer, explanation, type
progress      user_id, set_id, question_id, state(0未答|1对|2错|3掌握), correct_count, wrong_count, updated_at
wrong_items   user_id, question_id, count, last_at
favorites     user_id, question_id, created_at
attempt_logs  id, user_id, set_id, question_id, correct, created_at   （答题流水，聚合统计与热度）
stats_daily   user_id, day, answered, correct                        （近 7 天趋势）
upload_jobs   id, user_id, status, file_name, result_json, created_at （解析任务，大文件异步）
```

个人数据全部挂 `user_id`：换设备登录同一账号即可恢复；匿名设备登录则绑定设备。

## 6. API 设计

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/auth/register` | 用户名+密码注册（scrypt） |
| POST | `/api/auth/login` | 登录，返回 token |
| POST | `/api/auth/device` | 设备匿名登录（自动生成 device_id） |
| POST | `/api/auth/logout` | 退出 |
| POST | `/api/upload` | 上传文件（multipart），返回解析预览（不入库） |
| POST | `/api/sets` | 按解析预览入库（`{previewId, title, cat, tags, desc, visibility: public|private}`） |
| GET | `/api/sets?search&cat&sort&page&visibility` | 列表（公共库全可见；私库仅本人） |
| GET | `/api/sets/:id` | 题库元信息 |
| PATCH / DELETE | `/api/sets/:id` | 编辑/删除（owner 或 admin） |
| POST | `/api/sets/:id/questions` | 追加题目（复用上传解析） |
| GET | `/api/sets/:id/questions?offset&limit` | 题目分批（默认 20） |
| POST | `/api/quiz/:setId/start` | 建刷题会话（模式 order/random/daily/wrong） |
| GET | `/api/quiz/:setId/questions?offset&limit` | 会话内分批取题 |
| POST | `/api/quiz/answer` | 提交答题 `{questionId, correct, selfMark}` |
| POST | `/api/quiz/:id/finish` | 结束会话，返回汇总 + 更新统计 |
| GET | `/api/wrong?page` | 错题本（按次数排序） |
| POST/DELETE | `/api/wrong/:questionId` | 已掌握 / 移除 |
| GET/POST/DELETE | `/api/favorites/:questionId?` | 收藏 |
| GET | `/api/stats/me` | 我的统计（累计/趋势/错题数） |
| GET | `/api/stats/global` | 平台统计（题库数/题目数） |
| POST | `/api/import` | 迁移导入旧 localStorage 数据（JSON） |

## 7. 前端瘦身（浏览器不再被占用）

1. **移除**：`parser.js` 全部解析逻辑（含 PDF/Word 提取与 CDN 依赖）、localStorage 大题库存储。
2. **新增**：`api.js` token 管理（localStorage 仅存 token ~100B 与主题偏好）、SessionStorage 会话缓存（当前刷题会话最近 20 题，关页即清）。
3. **保留**：现有 UI/交互/深色模式/快捷键/移动端导航——只换数据源。
4. **内存**：刷题时仅持有当前 20 题 + 会话序号，题目索引（2048 个 idx）轻量缓存。
5. **兼容**：离线提示明确（服务器化后核心功能需联网）；可选 PWA 缓存静态资源。

## 8. 安全与健壮

1. 密码 scrypt 加盐哈希；token 随机 32B，7 天过期。
2. 权限：公共库所有人可读；私库/编辑/删除仅 owner；官方题库禁改删；可选 `HONGBI_ADMIN_KEY`。
3. 上传：限 20MB、文件类型白名单、解析结果清洗（长度/数量上限 3000 题）。
4. XSS：前端所有用户内容 `esc()` 转义（沿用）；服务器存储前清洗字段。
5. 解析隔离：解析任务失败不阻塞主流程；超大文件走异步 `upload_jobs` 队列（轮询结果）。

## 9. 迁移：旧数据怎么办

提供「数据迁移」入口（我的题库 → 导入本地数据）：
1. 浏览器读取旧 localStorage 的题库/错题/收藏/统计（一次性）。
2. `POST /api/import` 批量入库到当前账号（题库标为私库，避免未确认就进公共库）。
3. 成功后清除本地旧数据，提示重新上传原文件以获得最新解析效果（如辅警题库 2048 题版）。

2. M2 题库 API：sets/questions 分页 + 共享确认入库

## 11. 待确认决策

1. **账号体系**：A. 用户名+密码登录（正式多用户）；B. 仅设备匿名（免登录，换设备需迁移）；C. 两者都要（推荐，设备登录为默认免打扰）。
2. **npm 依赖**：A. 引入 Express + multer + pdfjs-dist（开发快，需一次 npm install）；B. 保持零依赖（自写路由/上传/PDF 解析，工作量大、PDF 解析不完整）。
3. **旧 localStorage 数据**：A. 提供一键迁移导入（推荐）；B. 不做迁移，让用户重新上传文件。
4. **公共库语义**：保持现状（共享即全员可见），还是加「贡献审核」队列（管理员批准后可见）？

## 12. 已确认决策（定稿）

1. **账号体系**：两者都要。默认设备匿名登录（免打扰）；可注册用户名+密码；登录后自动合并该设备的题库/进度/错题/收藏/统计到账号。
2. **npm 依赖**：接受。Express + multer + pdfjs-dist + jszip。运行：`npm install && node server/server.js`。
3. **旧数据**：提供一键导入（我的题库 → 导入本地数据），批量入库标私库，成功后清除本地副本。
4. **贡献审核**：上传选「同意共享」后进入 `pending` 审核队列，管理员批准后才进公共库；用户端显示 待审核/已通过/已驳回。
5. **上传限制**：100MB（`MAX_UPLOAD_MB` 环境变量可调）；白名单 `.docx/.pdf/.txt/.md/.csv/.tsv/.json`；解析清洗：题干 ≤5000、答案 ≤2000、解析 ≤3000、选项 ≤10 个、空题剔除、题数 ≤20000（`MAX_QUESTIONS` 可调）截断提示。
6. **角色体系（三级）**：
   - `superadmin` 超级管理员：全部权限，可管理管理员；
   - `admin` 管理员：审核队列、删除任何公共题库；
   - `user` 用户：常规使用；设备匿名登录为 user。
   - 管理员产生方式：设置 `HONGBI_ADMIN_KEY` 环境变量时，携带密钥的注册/升级请求成为 superadmin；未设置时，首位注册用户自动成为 superadmin。
7. **审核驳回**：必须填写驳回原因，反馈给上传者（我的贡献中可见）。
8. **上传失败提示**：包含具体原因（如「PDF 无法提取文字，可能为扫描件」「解析库加载失败」等）。
9. **超大题库**（>1000 题）：刷题页顶部提示建议用随机/每日一练模式；进度采用稀疏存储（只记录答过的题），万题库无压力。
